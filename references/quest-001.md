# 悬赏 No.001 — 失落的金色补给

> 剧本文件。游戏包装与真实数据严格分离：所有价格、商品、营养数据必须来自当次真实 MCP 返回，剧本文案只是包装。

## 任务背景（公会大厅文案）

> 冒险者，欢迎来到麦麦冒险者公会。
> 传闻金拱门遗迹深处埋藏着"失落的金色补给"——传说中由秘制酱料祝福、万中无一的黄金配置。
> 公会悬赏板上，这份任务正等待新的探索者。

## 任务参数

| 参数 | 说明 | 缺省处理 |
| --- | --- | --- |
| 城市 | 必须玩家提供（如"深圳市"） | 未提供则询问 |
| 位置关键词 | 用于门店搜索（如"深圳北站"） | 可用城市名重试 |
| 预算 | 单次任务总预算（元，内部计算换算为分） | 建议默认 40 元，可调整 |
| 挑战类型 | 预算挑战 / 热量挑战（≤目标 kcal） | 未选则默认预算挑战 |

## 任务流程

1. **设定条件**：收集城市、位置关键词、预算、挑战类型。
2. **确认领取**：展示任务目标与规则，**等待用户明确确认领取悬赏**；确认前不发起任何 MCP 查询，用户可在此阶段取消或修改条件。
3. **侦察门店**：`query-nearby-stores` → 展示实际返回的门店名称、地址、`distance` 字段及营业状态；距离单位未确认时不标注单位。多家门店时由玩家选择，不默认第一家。门店查询结果可能包含城市级兜底结果；若无法确认与目标地点的匹配关系，须展示实际地址并请玩家核对，不得仅凭接口成功就声称精确匹配。
4. **探索菜单**：玩家选择门店后 `query-meals` → 过滤无法可靠确认是食品的商品，按分类展示候选（名称+价格+code）。
5. **选择路线**：玩家选择单品或套餐；可查看**已实测套餐**的详情（见"套餐与特调边界"）。
6. **核验价格**：玩家选定商品后，用 `calculate-price` 核验组合实际价格（分→元展示）。
7. **优惠检定（可选）**：`query-store-coupons` 仅记录实际查询结果；**当前版本不把未经验证的带券算价用于通关判定**，券列表为空则无券路线照常进行。
8. **判定**：
   - 预算挑战：**只依据核验成功的价格**判定总价是否 ≤ 预算。
   - 热量挑战：只有每项商品都可靠匹配到营养数据且总量计算完成后，才允许判定达标；任一项缺失则标记"待核实"。
9. **结算**：按称号规则解锁，展示结算卡。

## 套餐与特调边界

1. 可以查看**已实测套餐**（开发样例：巨无霸三件套 code=9900005466）的详情。
2. 其他套餐、特调或加价组合，只有在实际 Schema 与参数规则已确认时才能尝试；未验证的组合**不得声称已核价成功**。
3. 价格核验失败时暂停结算，允许重新选品或重试。

## 达成判定与称号（虚构游戏成就，非麦当劳官方权益）

| 称号 | 解锁条件 |
| --- | --- |
| 初入公会 | 用户明确确认领取悬赏后解锁 |
| 寻宝学徒 | 门店查询和菜单查询均取得有效结果后解锁 |
| 菜单学者 | 成功读取至少一个套餐详情后解锁 |
| 任务全勘 | 适用挑战的核验成功且满足目标后解锁；未选择的可选步骤不要求完成 |
| 无券勇者 | 仅在优惠券查询成功返回空列表，且玩家最终达成挑战时解锁 |

## 异常与预约分支

| 情况 | 处理 |
| --- | --- |
| 门店查询无结果 | 展示真实错误/空结果，允许修改城市或关键词重试 |
| 门店打烊（businessStatus=false 或错误 600057） | 展示营业时间，建议换店；预约模式仅在门店返回对应可预约时段且工具参数已核实的情况下进行菜单查询 |
| 预约菜单查询 | 仅查询预约时段菜单，**不得描述成完成预约、下单或锁定名额** |
| 菜单查询失败 | 保留非敏感错误码，允许重试或换店 |
| 无可用优惠券 | 正常继续无券路线，空列表不是接口错误 |
| 营养数据缺失 | 标记"待核实"，不判定达标，允许换品重试 |
| 价格无法核验 | 状态为"暂停"或"待核实"，不判定玩家失败，不发放通关称号 |
| MCP 暂时不可用 | 暂停任务，提供重试或更换路线选项，不判定玩家失败 |
| 玩家主动退出或任务未达成 | 可生成状态卡，但必须明确标记"未完成"或"待核实"，细则见"结算卡边界"第 5 条 |

## 结算卡边界

1. 只将**当次真实返回**的数据写入结算卡；不得编造商品、价格、营养数据或优惠券。
2. 价格核验失败时，结算卡**不能展示未经核验的最终总价**。
3. 游戏称号和成就均为虚构内容，不是麦当劳官方优惠券、奖励或任何真实权益。
4. 使用 `assets/settlement-card.html` 模板填充当次真实数据；玩家放弃或失败时同样生成状态卡并标记任务状态，允许重试或更换路线。
5. **玩家主动退出时的结算规则**：
   - 若价格核验已成功，状态卡可以展示已成功核验的商品、数量和价格。
   - 任务状态必须标记为**"未完成（玩家主动退出）"**，不得因价格核验成功就自动认定整项任务完成。
   - 称号表示玩家已经满足的对应里程碑条件，与任务最终状态独立；玩家主动退出时，保留退出前已满足条件的称号，但仍须将任务状态标记为"未完成（玩家主动退出）"，不得因此显示整项任务通关。
   - 只保留退出前已满足解锁条件的称号；不得授予尚未满足条件的通关称号。
   - 未核验的价格、未查询的优惠券和未查看的套餐详情必须如实标记为**"待核实"或"未查询"**，不得用零值代替未知值。
